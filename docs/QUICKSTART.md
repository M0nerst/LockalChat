# Быстрая проверка LockalChat

## Один терминал (рекомендуется)

```bash
npm install
npm start
```

Откройте http://localhost:5173.

1. **Создать организацию** (Chrome).
2. Панель администратора → пользователь → **Экспорт invite**.
3. **Edge** (или Incognito): тот же URL → **Подключиться** → JSON + логин + пароль.
4. При **каждом входе** dev-сервер сам поднимает `lockal-daemon` (полоса сверху: сервис LAN / P2P-сессии).
5. Чаты или Контакты → диалог → сообщение. Список чатов — посередине, переписка справа (как в Telegram).

Отдельный `npm run dev:daemon` **не нужен**, если вы зашли через `npm start`.

---

## Требования

- Node.js 20+
- Rust + `lockal-daemon` (см. [DEVELOPMENT.md](DEVELOPMENT.md))
- Windows: `%USERPROFILE%\.cargo\bin` в PATH

```bash
npm install
npm test          # ~28 тестов
npm run build     # опционально
```

При первом `npm start` / `npm run build` копируется `sql-wasm.wasm` в `apps/desktop/public/` — без этого страница может остаться **белой**.

## Уровень 1 — UI и локальные данные (без LAN)

Проверяет: организация, RBAC, SQLite, сессии.

```bash
npm start
```

1. http://localhost:5173 → создайте организацию и admin
2. Панель администратора → пользователь `ivan`
3. Перезагрузите страницу — сессия должна сохраниться
4. **Выйти** → войдите снова как admin
5. Настройки: тема, язык, отпечаток устройства

Daemon для этого уровня не обязателен.

## Уровень 2 — P2P в LAN (два компьютера)

### ПК 1 (администратор)

```bash
npm start
```

1. Создайте организацию (если ещё нет)
2. Админ → пользователь → **Экспорт invite**
3. Передайте JSON и пароль коллеге (не одним письмом, если есть такая политика)

В production-сборке daemon стартует сам. В dev — тоже, после входа.

### ПК 2 (сотрудник)

1. Поставьте LockalChat (NSIS) **или** `npm start` из того же репозитория
2. **Подключиться** → invite JSON → логин + пароль + имя устройства
3. Оба ПК в одной подсети. Contacts / полоса статуса: устройства в LAN, P2P-сессии
4. Чаты → напишите сообщение, прикрепите файл

Если Join отвечает, что устройство **уже в организации**: Настройки → **Отвязать это устройство**, либо просто войдите — повторный Join на занятом локальном профиле запрещён.

**Без интернета** достаточно одной Wi‑Fi/LAN. LockalChat не поднимает VPN.

## Уровень 3 — два клиента на одном ПК

Два браузера (Chrome + Edge) — разный `localStorage`.

| Клиент | Браузер | Vite | UI WS | LAN port |
|--------|---------|------|-------|----------|
| Admin  | Chrome  | 5173 | 39201 | 39200    |
| Ivan   | Edge    | 5173 | 39202 | 39210    |

**Admin (Chrome):** организация → пользователь + invite → войти (daemon на портах по умолчанию).

**Ivan (Edge):** `/setup/join` → invite → Настройки → LAN `39210`, UI WS `39202`, Daemon URL `ws://127.0.0.1:39202` → Сохранить → **выйти и войти снова**.

Если нужен ручной второй daemon:

```bash
cargo run -p lockal-daemon -- --config path/to/ivan-daemon-config.json
```

`daemon-config.json` можно скачать из Настроек (расширенные порты).

npm run tauri:dev

## Частые проблемы

| Симптом | Решение |
|---------|---------|
| `cargo` не найден | Перезапустите терминал после rustup; `.cargo\bin` в PATH |
| Белый экран | `npm start` из корня, чтобы скопировать `sql-wasm.wasm` |
| LAN daemon offline | Войдите в аккаунт; в dev daemon поднимается сам. Иначе `npm run dev:daemon` с актуальным config |
| `Hostname must end with '.local.'` | Пересоберите daemon |
| Peers пусто | Одна org, оба daemon, одна подсеть; подождите 10–15 с |
| Join: уже принадлежит организации | Настройки → Отвязать это устройство, либо логин |
| Ivan не логинится на ПК2 | Invite JSON с ПК1 (с профилем пользователя) |
| Два daemon на одном ПК | Разные `lan_port` и `ui_ws_port` |
| Сообщение / файл не уходит | ⚠ в пузыре → повтор; Contacts → LAN peers |
